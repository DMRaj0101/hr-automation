## Existing Backend Fields
- employees: name, dept, manager, start/hireDate, email, office, title, id (as employee_id)
- tickets: id, issue, system, team
- checklists: system, platform
- dashboard: stats, departments (name/employees/openTickets), systemHealth, ticketStatus
- systemHealthDetail: name, status, latency
- onboardingDetails: startDate

## Derivable Fields
- employees: status, progress, blockers, remaining, yearsOfService
- tickets: employee (name via join), dept (via join or Ticket.role), status, time
- ticketDetails: statusHistory
- checklists: status, kind
- onboardingDetails: status/type
- monitoring: lastEvent, activeRequests
- chatMessages: text/source (live LLM, not scripted)
- meta: depts, roles, teams

## Missing Fields
- employees: type, est, phone, empManager, jobLevel
- ticketDetails: slaTotalHours, slaRemainingHours, slaPercentElapsed, errorType, errorCode, errorMessage, retryCount, nextRetry, notes[].author
- checklists: detail, outcome
- dashboard: integrationCoverage, slaWarning, departments[].avgCompletion
- onboardingDetails: plannedCompletion, daysRemaining, alerts[]
- monitoring: slaWarning
- suggestionChips, chipReplies
- users: entire list shape (id/name fields, list exposure)

## Missing APIs
- No unified per-employee "checklist" endpoint (profile.py keeps provisioning/tickets as two separate lists)
- No GET endpoint exposing users as a list
- No GET endpoint exposing meta filter options (depts/teams/roles)
- No single "ticket detail" endpoint with SLA/structured-error/history in one response
- routers/approvals.py is a stub with zero endpoints (not wired into main.py)
- health_check_orchestrator's and monitoring_agent's background loops are implemented but not started at app startup -- system-health/monitoring data can be stale or empty

## Overall Backend Readiness
Partially Ready. Core identity fields for employees and tickets, and the
system-health panel, are already backed by real backend code with only
minor renames needed. A second tier (progress ratios, per-employee ticket
aggregation, chatbot Q&A, filter metadata) is reachable with new queries
but no schema changes. The largest tier -- SLA tracking, structured error
detail, alerts/notifications, completion percentages, and the scripted
chatbot/user-list shapes -- has no backend concept today and needs new
models and product decisions before the frontend can be fully powered by
this backend.
